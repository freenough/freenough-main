## 作業A：320px幅の横あふれ確認（報告のみ・修正しない）

1. TOP（`/`）を、幅 **320 / 360 / 375 / 390** で開き、横スクロールが出ていないか確認する。
   - 判定：`document.documentElement.scrollWidth > window.innerWidth`
   - あふれている場合は、原因要素を特定する（`scrollWidth > clientWidth`の要素を列挙し、最も外側の要素と、はみ出している幅を報告）。
2. 「動きを減らす」設定をエミュレートした状態と、通常状態の両方で確認する（Revealの`transform`が一時的にあふれを作っていないかを切り分ける）。
3. **この作業では、あふれが見つかっても修正しない。** 原因と、修正案（1〜2案）だけ報告する。

## 作業C：`Reveal.tsx`の端のケース修正（実装する）

対象：`app/components/Reveal.tsx`

### 症状
途中までスクロールしてリロードすると、`.rv`の要素が表示されないまま残る場合がある。

### 想定される原因（実物で確認すること）
- 復元されたスクロール位置より**上にある**`.rv`は、IntersectionObserverが交差を検知せず、`opacity: 0`のまま残る。
- 背の高い要素は、画面に見える割合がthreshold 0.12に届かず、現れない。

### 修正方針（実物を見て、より小さい変更を選ぶ）
- 監視を始める時点で、要素が**すでに画面より上にある**（`getBoundingClientRect().bottom <= 0`）なら、即座に`in`を付ける（アニメーションなし、またはtransitionなしで）。
- 背の高い要素は、割合ではなく**見えている高さ**でも判定する（例：`intersectionRect.height`がviewportの高さの一定割合以上なら`in`を付ける）。
- 既存の確定値は**変えない**：24px／0.9秒／0.12秒の時間差、threshold 0.12、rootMargin `0px 0px -6% 0px`、4秒保険、`js-reveal`の仕組み。
- 動かすのは`opacity`と`transform`だけ、各要素1回だけ再生、は維持する。

### 検証
1. 次の3状態で、`.rv`の6個がすべて最終的に表示されることを確認する：
   - ページ中ほどまでスクロールしてからリロード
   - ページ最下部までスクロールしてからリロード
   - ハッシュ付きURL（アンカー位置）で直接開く
2. 通常のスクロール（上から順に読む）で、演出が従来どおり再生されること（24px／0.9秒／0.12秒の時間差）。
3. 「動きを減らす」設定、JS無効で、すべて表示されること。
4. 10幅（375, 390, 768, 799, 800, 1024, 1280, 1366, 1440, 1920）で、見た目の崩れとCLSがないこと。
5. `npm run build`が通ること。lintは、既存の2件（`Header.tsx:27`、`Footer.tsx:50`）以外が増えていないこと。
