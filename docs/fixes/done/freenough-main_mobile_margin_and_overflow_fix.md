## 作業1：スマホ幅の左右余白を16pxに揃える（案A）

対象：`app/page.tsx`のみ。`Header.tsx`・`Footer.tsx`は**変更しない**（lifecompass-nextと同じクラスを保つ方針）。

1. 本文の外側：`px-6` → `px-4 min-[800px]:px-6`
2. MESSAGEの帯：`-mx-6 px-6` → `-mx-4 px-4 min-[800px]:-mx-6 min-[800px]:px-6`（外側の余白と相殺して付け直す構造を保つ）
3. 800px以上の見た目は**1pxも変えない**。800px未満だけが変わる。
4. 外側の余白と相殺している箇所が、ほかにもないか実物のコードで確認する（見つかれば同じ扱いにして報告に書く）。

## 作業2：320px幅の横あふれを直す（案a）

あふれの原因（前回の報告）：
- 見出しh1の`<span class="whitespace-nowrap">あなたにとっての</span>`が、文字サイズ下限40px（`clamp(2.5rem, …)`）のため309pxになり、本文幅に入らない。
- ボタンの`min-w-[19rem]`（304px）が、2本柱の左ブロックの列幅を引っ張る。

修正：
1. 見出し：360px未満でだけ文字サイズの下限を下げ、`あなたにとっての`が本文幅に収まるようにする。
   - 作業1の後の本文幅は、320pxで288px。目安は下限36px前後（線形換算）だが、**実測で決める**（収まる最大の値を選ぶ）。
   - 360px以上の見出しは**変えない**。
   - `whitespace-nowrap`は外さない（折り返し位置を保つため）。
2. ボタン：`min-w-[19rem]` → `min-w-[min(19rem,100%)]`。360px以上の見た目は変えない。

## 検証（実物の本番ビルドで）

`npm run build` → `next start`、Playwrightで確認する（前回と同じ手順）。

1. **横あふれ**：幅 320 / 360 / 375 / 390 で`scrollWidth > innerWidth`が偽であること。通常と「動きを減らす」の両方。
2. **左端の揃い**：375 / 390 / 768 / 799で、ロゴ・本文・フッターの左端が16pxに揃っていること（実測値を表に）。800 / 1024 / 1280 / 1440で、作業前と**同じ値**であること（前回のスクリーンショット・実測値と比較）。
3. **360px以上の見出し**：360 / 375 / 390 / 768で、折り返し位置と文字サイズが作業前と同じであること。
4. **ボタン**：2本柱の左ブロックの列幅が、320pxでボタンに引っ張られていないこと。
5. **10幅**（375, 390, 768, 799, 800, 1024, 1280, 1366, 1440, 1920）の見た目とCLS（0であること）。スクリーンショットを撮り、作業前と並べて差分が意図どおりか目視する。
6. **Reveal**：作業Cの検証のうち、中ほどからリロード・最下部からリロードの2つを再実行し、6/6のままであること。
7. `npm run build`が通ること。lintは既存の2件（`Header.tsx:27`、`Footer.tsx:50`）のみ。
