# 実装指示書:モバイルヘッダー・HERO見出し・本文の改善(Freenough TOP)

## 背景

iPhone SE等の狭い画面幅で、以下3つの表示崩れが確認された:

1. ヘッダーナビの文字が折り返す(「資産シミュレータ/ー」のように単語途中で改行)
2. HERO見出しのフォントサイズが大きすぎ、4行に折り返り、しかも改行位置が不格好(「あなたにとっ/ての」等)
3. 本文段落が中央揃えのため、行ごとの余白が不揃いでガタついて見える

**このリポジトリの対応範囲:Freenough TOP(`freenough.com`)のみ。**

資産シミュレーターLP(`/asset-simulator`、`lifecompass-next`リポジトリ)側は既に同じ問題への対応が完了している。今回はその実装内容を踏襲し、TOP側にも同じ方針・同じ値を適用する。**LP側で確定した具体的な値をそのまま使うため、このリポジトリでは色や数値の再検討は不要。** ただし、コンポーネント構造やクラス名の付け方はLP側と異なる可能性があるため、Phase 1で該当箇所を特定してから実装すること。

---

## Phase 1:調査

以下を確認し、報告すること:
- ヘッダーコンポーネントのファイルパス(現状クライアント/サーバーコンポーネントいずれか)
- HEROセクション(見出し・本文段落)のファイルパス
- HERO見出しの現在のフォントサイズ指定方法(固定`text-*`クラスか)
- Tailwindの`text-balance`が使えるバージョンか(Tailwind CSS v3.4以降か)
- 既存のモバイル判定ブレークポイント(LP側は`lg:未満`を使用。TOP側で異なる場合は既存の値に合わせる)

---

## Phase 2:実装

### 2-1. ヘッダーのハンバーガーメニュー化

**対象:** モバイル判定ブレークポイント未満のときのみハンバーガー表示に切り替え。PC幅は現状の横並びナビのまま変更しない。

**ナビ項目(この順序で統一):**
1. シミュレーター(現行ラベル「資産シミュレーター」から短縮変更)
2. ブログ
3. ツール
4. Note(`https://note.com/freenough`)

- リンク先は現行の遷移先をそのまま使用(ラベルのみ変更)
- ロゴ(`FREENOUGH`)はヘッダー左に残し、右側にハンバーガーアイコンを配置。Tabler Icons `IconMenu2`/`IconX`を使用(LP側と同一)
- メニュー展開時、アイコンを`IconX`に切り替える
- ドロップダウンの開閉は`max-height`トランジション、`0.22s cubic-bezier(.4,0,.2,1)`(LP側と同一値)
- 展開方向:上から下(ヘッダー直下にナビ項目を縦に並べる)

### 2-2. 背景オーバーレイ

- **`bg-black/30`(LP側で確定した値、プロファイル管理ドロワーと同一)をそのまま使用**
- メニュー展開中、ヘッダー下から画面下端までオーバーレイを表示
- オーバーレイタップでメニューを閉じる
- オーバーレイはheaderの外側の兄弟要素として配置し、headerが作るスタッキングコンテキストにより、ドロップダウン項目が常にオーバーレイより上に描画される構成にする(LP側の実装と同一パターン)

### 2-3. HERO見出しのフォントサイズ・改行調整

対象見出し:「あなたにとっての『足りる』を、数字で描く。」

- フォントサイズを`clamp(2.25rem, 8vw, 3.75rem)`に変更(LP側と同一値。モバイル最小・PC最大とも現行値を目安に維持しつつ滑らかに補間する。現行のPC側フォントサイズが3.75remと異なる場合は現行値を上限として使う)
- `text-balance`クラスを追加
- 上記だけで改行位置が不自然な場合のみ、`<br>`による改行位置の手動指定を追加(スマホ幅限定、PC側に影響しない形にする)

### 2-4. 本文段落の左揃え化

- HERO直後の説明文について、モバイル幅で2行以上に折り返る段落は`text-left`に変更する
- 1行に収まる短い段落・サブコピーは中央揃えのまま維持してよい(LP側でも「1段落目は375px幅で1行に収まるため中央揃え維持、2段落目のみ左揃え」という判断をしており、同じ考え方で個別に判定すること)
- PC幅の表示は現状維持

---

## 実装後の確認事項

- iPhone SE幅(375px)相当のビューポートで、ヘッダー・HERO・本文それぞれ折り返しが解消されているか
- PC幅で従来の見た目から変化がないか
- ハンバーガーメニューの開閉、オーバーレイタップでの閉じる動作
- 実際のウィンドウリサイズが検証環境で効かない場合、LP側と同様にiframe幅指定+スクリーンショット+DOM計測で代替検証する
- 完了報告時は、変更したコンポーネント名・関数名を明記すること(行番号は編集中にズレるため使用しない)

## 参考:LP側(`lifecompass-next`)の実装サマリー(今回踏襲する内容)

- `src/components/layout/Header.tsx`をクライアントコンポーネント化。`lg:未満`でハンバーガーメニューに切り替え
- オーバーレイ:`bg-black/30`
- トランジション:`max-height` 0.22s `cubic-bezier(.4,0,.2,1)`
- HERO見出し:`clamp(2.25rem,8vw,3.75rem)` + `text-balance`
- 本文:段落ごとに1行で収まるかどうかで中央揃え/左揃えを個別判定
